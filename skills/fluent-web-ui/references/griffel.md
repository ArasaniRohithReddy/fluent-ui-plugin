# Griffel styling rules (`makeStyles`, `mergeClasses`, `shorthands`)

Fluent UI React v9 styles with **[Griffel](https://griffel.js.org)**, an atomic CSS-in-JS engine. Its failure mode is *silence*: break one of the rules below and you get no error, just the wrong pixels. Source for everything unless noted: [Styling components](https://storybooks.fluentui.dev/react/?path=/docs/concepts-developer-styling-components--docs).

---

## Rule 1 — `makeStyles` lives in module scope

> "To style a component, you need to call `makeStyles` in a **module scope** to create a React hook to be used inside a component."

```tsx
// ✅
const useStyles = makeStyles({ root: { color: tokens.colorNeutralForeground1 } });
function Component() {
  const classes = useStyles();
  return <div className={classes.root} />;
}

// ❌ new hook identity every render; also throws under Griffel's AOT compilation
function Component(props) {
  const useStyles = makeStyles({ root: { color: props.color } });
}
```
Related limitation: styles can't be created at runtime at all — no `props.color`, no dynamic selectors. Enumerate variants and pick with `mergeClasses`, or drop to an inline `style={{ … }}` for a genuinely free-form value. ([Griffel limitations](https://griffel.js.org/react/guides/limitations))

---

## Rule 2 — never concatenate class strings

> "**⚠ It is not possible to simply concatenate `useStyles` classes.** To properly merge the classes, you need to use `mergeClasses()` function, which performs merge and deduplication of atomic classes generated by `makeStyles()`."
> "`const wrongClasses = classes.root + ' ' + props.className;` // **Never concatenate class strings, always use `mergeClasses()`**"

```tsx
// ❌ both atomic classes land on the element; the winner is whichever CSS rule was inserted last
const bad = `${classes.root} ${props.className}`;
const alsoBad = clsx(classes.root, props.className);

// ✅ deduplicates on the atomic property level, so the intent is deterministic
const good = mergeClasses(classes.root, props.className);
```
This is not a style preference. Griffel emits one class per CSS declaration; two classes that both set `color` are a specificity coin-flip unless `mergeClasses` removes the loser.

---

## Rule 3 — order matters, and consumer `className` goes **last**

> "When `mergeClasses()` is called, it merges all classes from first to last — **the latter argument overwrites the previous ones** (similar to `Object.assign()`)."

```tsx
const classes = useStyles(); // blueBold: { color: 'blue', fontWeight: 'bold' }, red: { color: 'red' }

mergeClasses(classes.blueBold, classes.red); // { color: 'red',  fontWeight: 'bold' }
mergeClasses(classes.red, classes.blueBold); // { color: 'blue', fontWeight: 'bold' }
```

For a component that accepts `className` from its parent, that means exactly one correct order:

```tsx
// ✅ "these definitions have higher precedence"
<div className={mergeClasses(classes.root, props.className)} />

// ❌ upstream literally labels this "Incorrect order of classes"
<div className={mergeClasses(props.className, classes.root)} />
```
Conditional variants slot in between, and falsy values are fine:
```tsx
<div className={mergeClasses('ui-component', classes.root, props.primary && classes.rootPrimary, props.className)} />
```

## Rule 4 — `tokens.*`, never a raw value, never the CSS variable

> "`root: { color: 'red' }` // **Do not use colors directly as those are not theme-able. Always use colors from a theme**"

> "**⚠ Never use theme CSS variables directly!** The CSS variables implementation of the theme is internal to the library. We might eventually decide to change the variable names, hash them or even use direct values instead of some variables. **Always use the `tokens`** to access the theme."
> — [Theming](https://storybooks.fluentui.dev/react/?path=/docs/concepts-developer-theming--docs)

```tsx
const useStyles = makeStyles({
  ok:  { color: tokens.colorNeutralForeground3, padding: tokens.spacingHorizontalM },
  no1: { color: '#242424' },                          // ❌ not theme-able
  no2: { color: 'var(--colorNeutralForeground1)' },   // ❌ internal implementation detail
});
```
Look token names up with `fluent_get_token` / `fluent_list_tokens` — don't guess, and don't inline the value you find.

## Rule 5 — `shorthands` is now *mostly* legacy (verify before you copy old code)

This one is a live contradiction between two upstream sources, so know both:

- The **Storybook** [Styling components](https://storybooks.fluentui.dev/react/?path=/docs/concepts-developer-styling-components--docs) page still teaches `...shorthands.border('1px', 'solid', tokens.colorNeutralStroke1)` and states Griffel lacks *"support for CSS shorthand properties."* The Next.js SSR page still uses `shorthands.padding`/`gap`/`borderRadius`. **These pages lag.**
- **Griffel's own source** deprecates almost all of them: *"@deprecated Just use `{ gap: '10px 5px' }` instead as **Griffel supports CSS shorthands now**"* — [`packages/core/src/shorthands/gap.ts`](https://github.com/microsoft/griffel/blob/main/packages/core/src/shorthands/gap.ts), same tag on [`padding.ts`](https://github.com/microsoft/griffel/blob/main/packages/core/src/shorthands/padding.ts) and 18 more.

**Current rule: write native CSS shorthands.** Of the 23 functions exported from [`shorthands/index.ts`](https://github.com/microsoft/griffel/blob/main/packages/core/src/shorthands/index.ts), **20 are `@deprecated`**:

`border` · `borderTop` · `borderRight` · `borderBottom` · `borderLeft` · `borderRadius` · `flex` · `gap` · `gridArea` · `inset` · `margin` · `marginBlock` · `marginInline` · `outline` · `overflow` · `padding` · `paddingBlock` · `paddingInline` · `textDecoration` · `transition`

```tsx
// ❌ legacy
const useStyles = makeStyles({
  root: { ...shorthands.padding('10px'), ...shorthands.gap('8px'), ...shorthands.borderRadius(tokens.borderRadiusMedium) },
});

// ✅ current
const useStyles = makeStyles({
  root: { padding: tokens.spacingHorizontalM, gap: tokens.spacingVerticalS, borderRadius: tokens.borderRadiusMedium },
});
```

**Three are NOT deprecated and are still required** — Griffel still can't expand these, and writing them natively is a TypeScript error:

| Still required | Replaces |
|---|---|
| `shorthands.borderColor(a, b?, c?, d?)` | `borderColor` |
| `shorthands.borderStyle(a, b?, c?, d?)` | `borderStyle` |
| `shorthands.borderWidth(a, b?, c?, d?)` | `borderWidth` |

> "`borderColor: 'red'` // ❌ This is not supported, TypeScript compiler will throw, styles will not be inserted to DOM — Use shorthand functions to avoid writting CSS longhands"
> — [Griffel `shorthands` API](https://griffel.js.org/react/api/shorthands)

```tsx
// ✅ each value is a SEPARATE ARGUMENT — shorthands.borderColor('red blue') produces wrong results
const useStyles = makeStyles({ root: { ...shorthands.borderColor('red', 'blue') } });
```
`shorthands` is still exported from `@fluentui/react-components`, and Fluent's own `createFocusOutlineStyle` still calls `shorthands.borderColor`. So: don't rip `shorthands` out wholesale — replace the 20 deprecated ones, keep the three colour/style/width ones.

## Rule 6 — override components through `className` and slots, not CSS selectors

> "To override an appearance of a FUI component, you use the exactly same approach — you call `makeStyles`/`useStyles` in your code and pass the resulting classes through `props`."

```tsx
const useOverrides = makeStyles({
  button:     { color: tokens.colorNeutralForeground3 },
  buttonIcon: { ...shorthands.borderColor(tokens.colorNeutralStroke1), borderWidth: '1px', borderStyle: 'solid' },
});

const overrides = useOverrides();
<Button className={overrides.button} icon={{ className: overrides.buttonIcon, children: <CallEndRegular /> }} />
```
Slots take a `className` of their own — that's the supported way to reach inside a component. Never target Fluent's generated class names or `[class*=…]`; they are unstable. (Stable per-component `*ClassNames` maps are exported if you truly need a selector.)

## Debugging

The [Griffel devtools Chrome extension](https://chrome.google.com/webstore/detail/griffel-devtools/bejhagjehnpgagkaaeehdpdadmffbigb) *"shows all griffel styles applied on the currently selected DOM element, including the styles that are overridden in `mergeClasses`"* — the fastest way to find out which of two competing classes won.
