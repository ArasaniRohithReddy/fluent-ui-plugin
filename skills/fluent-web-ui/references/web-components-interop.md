# React v9 + Web Components / shadow DOM interop

Two different questions get called "interop". Answer the right one:

| Question | Answer |
|---|---|
| "Can I put `<fluent-button>` (Web Components v3) in the same app as `<Button>` (React v9)?" | Yes — they are independent libraries over the same tokens. See *Mixing the two libraries* below. |
| "Can I render **Fluent React** inside a shadow root?" | Yes, but only with the `@fluentui-contrib` packages and three non-obvious rules. |

Source: [Using Fluent React with Web Components](https://storybooks.fluentui.dev/react/?path=/docs/concepts-developer-web-components-interop-using-fluent-react-with-web-components--docs). The rendered page drops its code blocks; snippets are from [`UsingFluentReactWithWebComponents.mdx`](https://github.com/microsoft/fluentui/blob/master/apps/public-docsite-v9/src/Concepts/WebComponentsInterop/UsingFluentReactWithWebComponents.mdx).

> "It is necessary to modify Fluent React v9's default behavior to better interoperate with Web Components. **The implementation lives in the [Fluent UI Contrib repository](https://github.com/microsoft/fluentui-contrib)**."

That sentence is the headline: none of this is in `@fluentui/react-components`. The three packages, all `0.x`, all separate installs:

```bash
npm i @fluentui-contrib/react-shadow @fluentui-contrib/react-themeless-provider @fluentui-contrib/pierce-dom
```

## Rule 1 — `FluentProvider` must be in the **light** DOM

```tsx
import { root } from '@fluentui-contrib/react-shadow';
import { FluentProvider, webLightTheme, Button } from '@fluentui/react-components';

// ✅ provider outside, shadow root inside
<FluentProvider theme={webLightTheme}>
  <root.div>{/* this is the shadow root */}
    <Button>Fluent React Button in shadow DOM</Button>
  </root.div>
</FluentProvider>;
```
```tsx
// ❌ "This will not render correctly, for example purposes only"
<root.div>
  <FluentProvider theme={webLightTheme}>
    <Button>Fluent React Button in shadow DOM</Button>
  </FluentProvider>
</root.div>;
```
> "⚠️ `FluentProvider` must be in the light DOM for this method to work." — when it sits inside the shadow DOM, *"styling/theming will not work as expected."*

Styles reach the components through the shadow root's `adoptedStyleSheets`.

## Rule 2 — a provider that must live inside shadow DOM is `ThemelessFluentProvider`, and **you** then own the theme CSS

> "`ThemelessFluentProvider` is a special version of `FluentProvider` … It supports the same features as `FluentProvider` except: 1. **It does not insert styles into the DOM** 2. **It removes the theming related contexts**."

So there is no theme unless you create one and make it pierce the shadow boundary — *"defined in such a way that they will pierce the shadow DOM (e.g., on the `:root` selector)"*:

```tsx
import { createCSSStyleSheetFromTheme, ThemelessFluentProvider } from '@fluentui-contrib/react-themeless-provider';
import { root } from '@fluentui-contrib/react-shadow';
import { webLightTheme, Button } from '@fluentui/react-components';

// Create theme styles OUTSIDE of React component rendering
const themeSheet = createCSSStyleSheetFromTheme(':root', webLightTheme);
document.adoptedStyleSheets = [...document.adoptedStyleSheets, themeSheet];

const ShadowDOMApp = () => (
  <ThemelessFluentProvider>
    <root.div>{/* shadow root */}
      <Button>Fluent React Button in shadow DOM</Button>
    </root.div>
  </ThemelessFluentProvider>
);
```

## Rule 3 — Tabster cannot see through shadow DOM; opt in **before** rendering

This is the silent one: nothing throws, components render, and keyboard navigation is simply wrong.

> "Fluent React uses [Tabster](https://tabster.io/) to control keyboarding and **it must be able to 'see' the entire DOM of a page to function correctly**. Since shadow DOM 'hides' parts of the DOM from Tabster, you must opt into shadow DOM support when using shadow DOM and Tabster together."

```tsx
import { useShadowDOMSupport } from '@fluentui-contrib/pierce-dom';

const AppComponent = () => {
  useShadowDOMSupport();   // "This must be called _before_ you render any Fluent React controls"
  return (
    <ThemelessFluentProvider>
      <root.div>
        <Button>First Button</Button>
        <Button>Second Button</Button>
      </root.div>
    </ThemelessFluentProvider>
  );
};
```
Ordering matters — call it above every Fluent control in the tree, not next to the one you're debugging. (Same failure family as the focus hooks in the `fluent-accessibility` skill: focus goes wrong quietly, no error.)

## Insertion point — making non-Griffel CSS win

> "`mergeClasses` can accept any CSS class name but it **only performs rule ordering for class names generated by Griffel**. This can lead to CSS specificity issues when you want to use CSS classes that were not generated by Griffel (for example, application utility classes)."

`mergeClasses` cannot arbitrate between a Griffel atomic class and your `.my-utility` class — so control it through **document order** instead, with a sentinel stylesheet:

```tsx
import { createRoot } from '@fluentui-contrib/react-shadow';

// This `CSSStyleSheet` acts as a sentinel for inserting Griffel styles.
// Griffel styles are inserted AFTER `insertionPoint`.
const insertionPoint = new CSSStyleSheet();
const root = createRoot({ insertionPoint });

const nonGriffelStyles = new CSSStyleSheet();
nonGriffelStyles.insertRule('.my-style-from-outside-fluent { color: red; }');

// Griffel lands between the two, so `nonGriffelStyles` appears later and "wins".
const externalStyleSheets = [insertionPoint, nonGriffelStyles];

<ThemelessFluentProvider>
  <root.div styleSheets={externalStyleSheets}>
    <Button className="my-style-from-outside-fluent">Button with external style</Button>
  </root.div>
</ThemelessFluentProvider>;
```
Related: [`mergeClasses`](https://griffel.js.org/react/api/merge-classes) and `references/griffel.md` → Rule 2/3.

## Mixing the two libraries in one app

React v9 (`@fluentui/react-components`) and Web Components v3 (`@fluentui/web-components`) are separate implementations of the same design language. They can coexist, but nothing is shared automatically:

- **Two theming systems.** React themes through `FluentProvider`; v3 has **no provider element** — you call `setTheme(theme, node?)`. Theme both, from the same `@fluentui/tokens` theme object, or the two halves of the page drift.
- **Registration is a side-effect import** for v3 (`import '@fluentui/web-components/button.js'`), not a class import. Both facts are in `../SKILL.md` → *Web Components v3*.
- Custom elements in JSX are plain DOM: attributes are strings, and events are native `CustomEvent`s reached with `ref` + `addEventListener`, not React `on*` props (React ≥19 improves this).
- Fluent React components that portal (`Dialog`, `Popover`, `Menu`, `Tooltip`) escape a custom element's subtree — expect them in the portal mount node, not next to their trigger.

> There is **no** official Angular/Vue/Blazor wrapper documented for Web Components v3. Treat any such guidance as unverified.
